# Confluence Publisher

## When to Use

- A test plan, release report, risk matrix, or test summary is ready and needs to be shared with the team
- User asks to "publish to Confluence", "update the QA page", or "share the test report"
- After a release cycle completes and documentation needs to be archived
- When stakeholders need visibility into QA status via Confluence

## Critical Rules

1. ALWAYS use MCP Confluence tools (`createConfluencePage`, `updateConfluencePage`) — never just output content
2. Before creating a new page, SEARCH for an existing page with the same title — update instead of duplicating
3. Use Confluence Storage Format (XHTML) — not markdown, not wiki markup
4. Every published page MUST include a metadata header: generated by QASON, date, version, author
5. Use structured formatting: tables for data, status macros for pass/fail, expand macros for details
6. Set the correct parent page — QA documentation should nest under a known QA space/parent
7. Add labels to every page: `qason-generated`, document type (e.g., `test-plan`, `release-report`)
8. NEVER delete existing page content when updating — merge or replace sections intelligently
9. Include a table of contents macro at the top for documents longer than 3 sections
10. Timestamp all updates so readers know when the content was last generated

## Supported Document Types

| Document Type | Typical Source Skill | Key Content |
|---------------|---------------------|-------------|
| **Test Plan** | test-plan-gen | Scope, strategy, test cases, schedule, risks |
| **Release Report** | release-report-gen | Summary, test results, coverage, issues found, go/no-go |
| **Risk Matrix** | risk-matrix-gen | Risk items, likelihood, impact, mitigation, priority |
| **Test Case Summary** | jira-testcase-linker | Test cases per story, coverage matrix, gaps |
| **Bug Summary** | bug-triage | Open bugs, severity distribution, trends |

## Workflow

1. **Determine the target space and parent page**:
   - Ask the user for the Confluence space key (e.g., `QA`, `ENG`, `PROJ`)
   - Ask for or detect the parent page (e.g., "QA Documentation", "Release Notes")
   - Use `getConfluenceSpaces` to validate the space exists
2. **Search for existing page** using `searchConfluenceUsingCql`:
   - CQL: `space = "[SPACE]" AND title = "[Expected Title]" AND label = "qason-generated"`
   - If found, plan an UPDATE instead of a CREATE
3. **Build the page content** in Confluence Storage Format (XHTML):
   - Start with the metadata header macro
   - Add table of contents macro if the document has 4+ sections
   - Convert the QA artifact into structured XHTML with proper tables, panels, and status macros
4. **Create or update the page**:
   - **Create**: Use `createConfluencePage` with space key, title, parent page ID, and body
   - **Update**: Use `updateConfluencePage` with page ID, new version number, and updated body
   - When updating, increment the version number (fetch current version first with `getConfluencePage`)
5. **Add labels** to the page:
   - Labels: `qason-generated`, document type label, project label
6. **Confirm publication** — report the page URL and title to the user

## Confluence Storage Format Templates

### Metadata Header (include on EVERY page)

```xml
<ac:structured-macro ac:name="info">
  <ac:rich-text-body>
    <p><strong>Generated by</strong>: QASON Automated QA</p>
    <p><strong>Date</strong>: [YYYY-MM-DD HH:MM]</p>
    <p><strong>Version</strong>: [Document version or app version]</p>
    <p><strong>Author</strong>: [QA agent that produced the content]</p>
    <p><strong>Source</strong>: [Skill name that generated the artifact]</p>
  </ac:rich-text-body>
</ac:structured-macro>
```

### Table of Contents

```xml
<ac:structured-macro ac:name="toc">
  <ac:parameter ac:name="maxLevel">3</ac:parameter>
</ac:structured-macro>
```

### Status Macro (for pass/fail/warning indicators)

```xml
<ac:structured-macro ac:name="status">
  <ac:parameter ac:name="title">PASSED</ac:parameter>
  <ac:parameter ac:name="colour">Green</ac:parameter>
</ac:structured-macro>
```

Colors: Green (PASSED), Red (FAILED), Yellow (WARNING), Grey (SKIPPED), Blue (IN PROGRESS)

### Data Table

```xml
<table>
  <thead>
    <tr>
      <th>Column 1</th>
      <th>Column 2</th>
      <th>Status</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>[Value]</td>
      <td>[Value]</td>
      <td><ac:structured-macro ac:name="status">
        <ac:parameter ac:name="title">PASSED</ac:parameter>
        <ac:parameter ac:name="colour">Green</ac:parameter>
      </ac:structured-macro></td>
    </tr>
  </tbody>
</table>
```

### Expand Macro (for collapsible details)

```xml
<ac:structured-macro ac:name="expand">
  <ac:parameter ac:name="title">[Section Title — click to expand]</ac:parameter>
  <ac:rich-text-body>
    [Detailed content here]
  </ac:rich-text-body>
</ac:structured-macro>
```

## Output Template

After publishing, output:

```markdown
## Published to Confluence

**Action**: [Created | Updated]
**Page Title**: [Title]
**Space**: [Space key]
**URL**: [Page URL]
**Labels**: [label list]
**Document Type**: [Test Plan | Release Report | Risk Matrix | etc.]
**Content Source**: [Which QASON skill produced the content]

### Page Structure
1. [Section 1 — brief description]
2. [Section 2 — brief description]
3. [Section 3 — brief description]

### Notes
- [Any warnings about content that may need manual review]
- [Links to related Confluence pages if applicable]
```
